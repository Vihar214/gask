# Agent Instructions — gask (Task-CLI)

## Binary Name

The project binary is always called `gask`. Built with `go build -o gask`.
Run as `./gask <command>`. Never refer to it as `task` — that conflicts with system binaries.

---

## Commands

### Development

- `go run main.go <command>` → compile + run in one step, use during development
- `go build -o gask` → compile to local binary, use to verify final behavior
- `go generate ./ent/...` → regenerate Ent ORM code after any schema change — ALWAYS run this after editing ent/schema/

### Dependencies

- `go get <pkg>` → add a dependency (always ask before doing this)
- `go mod tidy` → remove unused deps, add missing ones — run after any dependency change
- `go list -m all` → inspect current dependency tree

### Testing

- `go test ./...` → run all tests
- `go test ./internal/db/...` → run only DB layer tests
- `go test -run TestName ./...` → run a single test by name
- `go test -v ./...` → verbose output, shows each test name and result
- Always run `go test ./...` before considering any task complete

### Database

- The DB file is `.gask.db` in the current working directory
- Delete `.gask.db` to reset local state during development
- Run `go generate ./ent/...` after every schema change — never hand-edit generated files

## Folder Structure

```
gask/
├── main.go               # Entry point — calls cmd.Execute() only, no logic here
├── go.mod                # Dependency manifest
├── go.sum                # Dependency lock file
├── cmd/                  # CLI command definitions (Cobra subcommands)
│   ├── root.go           # Base 'gask' command, persistent flags, global config
│   ├── add.go            # 'gask add' — opens $EDITOR, inserts task to DB
│   ├── list.go           # 'gask list' — queries DB, renders Lip Gloss table
│   └── status.go         # 'gask status <id> <status>' — updates task state
├── internal/             # Private application code — never imported externally
│   ├── db/
│   │   ├── sqlite.go     # DB init, driver setup, auto-migration on startup
│   │   ├── repository.go # SINGLE source of all DB access — all CRUD lives here
│   │   └── task.go       # Task struct and its DB mapping
│   └── editor/
│       └── editor.go     # Spawns $EDITOR, manages temp files, reads buffer output
└── ent/                  # AUTO-GENERATED by Ent ORM — never edit files here manually
    └── schema/           # The only folder in ent/ you ARE allowed to edit
        └── task.go       # Task schema definition — edit this, then run go generate
```

**Rule:** If you are adding logic, ask yourself which layer it belongs to:

- User input / flags → `cmd/`
- Business logic / validation → `internal/`
- DB queries → `internal/db/repository.go` only
- UI rendering → `cmd/` using Lip Gloss

## Patterns We Use

### Repository Pattern

All DB access lives in `internal/db/repository.go`. Nothing else touches the DB.

```go
// CORRECT — call repository from cmd/
tasks, err := repo.GetAll(ctx)

// WRONG — never do this in cmd/ or anywhere outside internal/db/
rows, _ := db.QueryContext(ctx, "SELECT * FROM tasks")
```

### Struct-Based Validation

Map all user input to a typed struct and validate before any processing.

```go
// CORRECT
type AddRequest struct {
    Title string `validate:"required,min=3,max=120"`
}
req := AddRequest{Title: args[0]}
if err := validate.Struct(req); err != nil { ... }

// WRONG — never trust raw args directly
db.Insert(args[0])
```

### Error as Values

Always return `(T, error)`. Wrap with context. Never panic in application code.

```go
// CORRECT
task, err := repo.GetByID(ctx, id)
if err != nil {
    return fmt.Errorf("status: getting task %d: %w", id, err)
}

// WRONG
task := repo.GetByID(ctx, id) // ignoring error
```

### Temporary File Lifecycle

Always defer cleanup immediately after creating temp files — no exceptions.

```go
f, err := os.CreateTemp("", "gask-*.md")
if err != nil { return err }
defer os.Remove(f.Name()) // immediately after creation, not at the end of the function
```

### Context Propagation

`context.Context` flows from `main.go` down to the DB layer on every call.
Never create a new `context.Background()` inside internal/ — accept one as a parameter.

## Off Limits

- **Never** run `git add`, `git commit`, `git push`, or `git rebase`
- **Never** add a package to `go.mod` without stating the package name and reason first
- **Never** edit any file inside `ent/` except `ent/schema/` — the rest is generated
- **Never** put SQL queries or ORM calls inside `cmd/` — that is repository.go's job
- **Never** run `os.RemoveAll` or delete `.gask.db` without an explicit instruction
- **Never** use `panic()` in application code — return errors instead
- **Never** create a new `context.Background()` inside `internal/` — propagate from caller

## Environment

### Editor Dependency

The tool requires `$EDITOR` to be set (expects `nvim`).

- If `$EDITOR` is unset: the `add` command must return a clear error — `"$EDITOR is not set. Export EDITOR=nvim or any editor."` — never silently fail or hang.
- Never hardcode `nvim` — always read from `os.Getenv("EDITOR")`.

### Local DB

- DB file: `.gask.db` in the current working directory (project-local by design)
- No `.env` file needed — no external services, no credentials
- To reset: `rm .gask.db` then re-run any command (auto-migration recreates the schema)

### Build & Verify Cycle

```
1. Edit code
2. go generate ./ent/... (if schema changed)
3. go test ./...        (must pass)
4. go build -o gask     (must compile)
5. ./gask <command>     (manual verify)
```

Never skip step 3. If tests fail, fix them before proceeding.
